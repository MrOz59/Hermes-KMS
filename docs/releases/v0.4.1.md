# Hermes-KMS 0.4.1 — release candidate

Maintenance companion to the October Hermes/Hestia release. This file tracks
preparation; 0.4.1 is not published yet. UAPI remains **14** and existing 0.4.0
consumers retain the same ioctl layouts and capability negotiation.

## Changes since 0.4.0

- Restore effective active-seat capture access and keep host/private render-node
  ACLs read-only, preventing Chromium/Electron from selecting a capture-only
  card as a rendering GPU (#11, #14; Hermes-KMS #6/#13).
- Build on Linux 6.17/6.18 by selecting `hrtimer_setup()` from the target
  headers when the older `hrtimer_init()` is unavailable (#12, @SOVLOOKUP).
- Run private seat brokers with `SEATD_VTBOUND=0`, without
  `CAP_SYS_TTY_CONFIG`, so opening an isolated session does not change the
  desktop's virtual-terminal mode (#16; Hermes #57).
- Refresh configfs, HDR, access-control and compositor documentation to match
  the implemented driver and its remaining validation limits (#17).
- Build both split packages in CI; pin release package sources to the exact
  commit and include source, build recipe and SHA-256 checksums.

HDR, session pools and runtime configfs displays already shipped in 0.4.0;
they are not new features of this patch release. NVIDIA direct-import tools
from experimental PR #15 are outside this candidate. NVENC retains its current
CPU-copy fallback; this release does not establish NVIDIA zero-copy support.

## Upgrade

1. Stop active streams and isolated compositors before updating. Install the
   DKMS package with the headers matching every kernel it must support. The
   optional seatd package is needed for private seat-broker sessions.
2. Verify the release's `SHA256SUMS`, then install the packages together using
   `sudo pacman -U` with their exact filenames. Confirm `dkms status` reports
   the new package version installed for the kernel you will boot.
3. Reboot to activate the new module. Updating files or rebuilding DKMS does
   not replace an already loaded kernel module. Existing configuration in
   `/etc/modprobe.d` continues to override packaged defaults.
4. After reboot, inspect `journalctl -k -g hermes-kms`, start a normal stream,
   then test an isolated session and confirm the host desktop remains usable.

Keep the previous packages for rollback. Reinstall both matching packages,
confirm DKMS rebuilt successfully, and reboot. Do not force-unload the module
while a compositor or consumer holds its resources.

## Cutting the release

The CI workflow builds candidate artifacts on every push/PR. For the final
reviewed commit, run `bash scripts/check-release-version.sh v0.4.1`, create an
annotated `v0.4.1` tag and push it. `Release` reruns the full CI suite, then
creates a **draft** release with the two packages, source archive, pinned
PKGBUILD, install hooks, source commit and checksums. It does not publish the
draft. Its manual trigger builds/validates artifacts without creating a release.

Driver and host versions are independent: PyroWave decoding is a client/host
integration and libvirtualhid is a host input backend. Neither requires a
driver UAPI bump. Gamescope isolation must still be tested against the exact
driver, broker and host candidates together.
