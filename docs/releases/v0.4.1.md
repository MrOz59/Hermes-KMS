# Hermes-KMS v0.4.1 — maintenance release

This maintenance release accompanies the October Hermes/Hestia integration.
The public UAPI remains **14**, and 0.4.0 consumers retain the same ioctl
layouts and capability negotiation.

**Validation scope:** The seven CI jobs passed before release, including
kernel builds and native package payload checks. The disposable-VM runtime
suite, real GPU/HDR/streaming and concurrent Gamescope sessions have **not**
all been verified for these exact release artifacts. Treat those deployments
as requiring additional validation; see the open checks below.

## Changes since 0.4.0

- Restore effective active-seat capture access and keep host/private render-node
  ACLs read-only, preventing Chromium/Electron from selecting a capture-only
  card as a rendering GPU (#11, #14; Hermes-KMS #6/#13).
- Build on Linux 6.17/6.18 by selecting `hrtimer_setup()` from the target
  headers when the older `hrtimer_init()` is unavailable (#12, @SOVLOOKUP).
- Run private seat brokers with `SEATD_VTBOUND=0`, without
  `CAP_SYS_TTY_CONFIG`, so opening an isolated session does not change the
  desktop's virtual-terminal mode (#16; Hermes #57).
- Refresh configfs, HDR, access-control and compositor documentation to match
  the implemented driver and its remaining validation limits (#17).
- Fix the 32-bit legacy `GET_STATUS` translation copying eight bytes past
  the native status structure. The old v10 userspace layout is preserved with
  a compile-time size guard; UAPI remains 14 (isolated fix from PR #15).
- Build the two Arch split packages and two native Debian/Ubuntu `.deb`
  packages and Fedora `.rpm` packages in CI, verifying DKMS source payloads
  and lifecycle scripts. Pin the release to the exact source commit; bundle
  source, build recipe and unified SHA-256 checksums.
- Clarify Bazzite/bootc instructions following a Fedora 44 Bazzite VM test:
  match the installed base image, re-layer Hermes after `bootc switch`, and
  log in to obtain `uaccess` render-node permissions (PR #20).

HDR, session pools and runtime configfs displays already shipped in 0.4.0;
they are not new features of this patch release. NVIDIA direct-import tools
from experimental PR #15 are outside this candidate. NVENC retains its current
CPU-copy fallback; this release does not establish NVIDIA zero-copy support.

## Upgrade and installation

Before upgrading, stop active streams and isolated compositors. Preserve the
previous 0.4.0 packages for rollback and install the kernel headers/devel
package matching the kernel you intend to boot. Verify the downloaded
`SHA256SUMS` against the release assets before installation.

### Arch / CachyOS

Install the core package; install the optional private seatd broker only if
you use isolated sessions:

```bash
sudo pacman -U ./hermes-kms-dkms-git-*.pkg.tar.zst
sudo pacman -U ./hermes-kms-seatd-git-*.pkg.tar.zst  # optional
```

### Ubuntu / Debian

Use `apt` so dependencies are resolved automatically:

```bash
sudo apt install ./hermes-kms-dkms_0.4.1-1_all.deb
sudo apt install ./hermes-kms-seatd_0.4.1-1_all.deb  # optional
```

### Fedora Workstation (mutable installation)

The published native RPMs are built for **Fedora 44**. On other Fedora
versions, rebuild the spec for that target rather than assuming the Fedora 44
RPM has been runtime-tested there:

```bash
sudo dnf install ./hermes-kms-dkms-0.4.1-1.fc44.noarch.rpm
sudo dnf install ./hermes-kms-seatd-0.4.1-1.fc44.noarch.rpm  # optional
```

**Bazzite / bootc:** do not install the mutable Fedora DKMS RPM in an
immutable image. Follow the image-based method in the README instead.

### After the upgrade

Confirm `dkms status -m hermes-kms` reports 0.4.1 as installed for the
kernel you will boot. DKMS success is separate from module signing: an
untrusted module may be rejected under Secure Boot. **Reboot** to activate
the new module; replacing package files cannot replace a module already
loaded into the kernel. Check `journalctl -k -g hermes-kms` after boot.

For optional private sessions, configure the selected user with
`sudo /usr/lib/hermes-kms/hermes-kms-setup configure --user auto` and
validate a normal stream before enabling multiple isolated sessions.

Rollback by reinstalling both matching previous packages, rebuilding the
previous DKMS module and rebooting. Do not force-unload an in-use virtual
DRM/KMS card or compositor session.

encoder, so a Hermes-KMS hardware-encoded stream, HDR and concurrent isolated

## Distribution and provenance

The release includes the Arch/CachyOS DKMS and seatd split packages, native
Ubuntu/Debian DEB packages, Fedora 44 RPM packages, an exact-commit source
archive, PKGBUILD and install hooks, `SOURCE_COMMIT` and unified
`SHA256SUMS`. The release workflow checks package checksums and source commit
identity before publishing.

CI verifies packaging and kernel-header compatibility, not successful runtime
installation on every distribution. Any Fedora/Debian/Ubuntu combinations
outside the built/tested package targets need additional validation.

Driver and host versions are independent: PyroWave decoding is a client/host
integration and libvirtualhid is a host input backend. Neither requires a
driver UAPI bump. Gamescope isolation must still be tested against the exact
driver, broker and host candidates together.

For an ecosystem installer, use the platform detection, matching-kernel DKMS
checks and immutable-system safeguards in [docs/installer-contract.md](../installer-contract.md).
