# Hermes-KMS v0.4.1

A maintenance update for the Hermes virtual DRM/KMS display driver, focused on
kernel compatibility, desktop safety and more reliable distribution packages.

**Driver:** 0.4.1 · **UAPI:** 14 (unchanged from 0.4.0) · **Release:** 2 November 2026

> **Kernel driver notice:** An out-of-tree DRM module can disrupt a desktop
> session. Stop active streams before upgrading, keep a rollback option and
> reboot after replacing an already loaded module.

## What's new in 0.4.1

- **Read-only capture access.** Restore the active desktop user's render-node
  permissions while restricting capture nodes to read-only access. This stops
  generic applications such as Chromium/Electron from treating Hermes-KMS as
  a rendering GPU. Thanks to @PunkUnity for the active-seat fix
  ([#11](https://github.com/MrOz59/Hermes-KMS/pull/11)); the read-only policy
  was finalized in [#14](https://github.com/MrOz59/Hermes-KMS/pull/14).
- **Linux 6.17/6.18 compatibility.** Select the newer `hrtimer_setup()` API
  when the kernel headers no longer provide `hrtimer_init()`. Contributed by
  @SOVLOOKUP ([#12](https://github.com/MrOz59/Hermes-KMS/pull/12)).
- **Safer isolated sessions.** Private seatd brokers now use
  `SEATD_VTBOUND=0` and no longer require `CAP_SYS_TTY_CONFIG`, preventing
  them from taking control of the host desktop's virtual terminal
  ([#16](https://github.com/MrOz59/Hermes-KMS/pull/16)).
- **32-bit compatibility fix.** Correct an eight-byte kernel stack over-read
  in the legacy `GET_STATUS` translation while preserving the existing
  userspace layout. The fix was isolated from the experimental work in #15;
  **UAPI 14 is unchanged**
  ([#21](https://github.com/MrOz59/Hermes-KMS/pull/21)).
- **Better packaging.** Ship validated Arch/CachyOS, Ubuntu/Debian and
  Fedora 44 packages, with core DKMS and optional private seatd components.
  The release also includes source and SHA-256 checksums
  ([#18](https://github.com/MrOz59/Hermes-KMS/pull/18),
  [#21](https://github.com/MrOz59/Hermes-KMS/pull/21)).
- **Bazzite documentation.** Updated instructions for matching the installed
  base image, re-layering Hermes after a `bootc switch`, and waiting for
  desktop login before expecting `uaccess` permissions. Thanks to
  @PunkUnity for testing the setup in a Bazzite VM
  ([#20](https://github.com/MrOz59/Hermes-KMS/pull/20)).

HDR capture, cursor capture, runtime configfs displays and session pools were
already included in **0.4.0**; they are not new 0.4.1 features.
Experimental NVIDIA direct-import/zero-copy work is **not** included.

## Download and install

The **Assets** below contain six packages: a core DKMS driver and an optional
`seatd` session-broker package for each supported package format.
Download the matching files and verify them against `SHA256SUMS`.

| System | Required driver | Optional private sessions |
| --- | --- | --- |
| Arch / CachyOS | `hermes-kms-dkms-git-*.pkg.tar.zst` | `hermes-kms-seatd-git-*.pkg.tar.zst` |
| Ubuntu / Debian | `hermes-kms-dkms_0.4.1-1_all.deb` | `hermes-kms-seatd_0.4.1-1_all.deb` |
| Fedora 44 Workstation | `hermes-kms-dkms-0.4.1-1.fc44.noarch.rpm` | `hermes-kms-seatd-0.4.1-1.fc44.noarch.rpm` |

**Arch / CachyOS**

```bash
sudo pacman -U ./hermes-kms-dkms-git-*.pkg.tar.zst
# Optional, for isolated sessions:
sudo pacman -U ./hermes-kms-seatd-git-*.pkg.tar.zst
```

**Ubuntu / Debian**

```bash
sudo apt install ./hermes-kms-dkms_0.4.1-1_all.deb
# Optional, for isolated sessions:
sudo apt install ./hermes-kms-seatd_0.4.1-1_all.deb
```

**Fedora 44 Workstation (mutable system)**

```bash
sudo dnf install ./hermes-kms-dkms-0.4.1-1.fc44.noarch.rpm
# Optional, for isolated sessions:
sudo dnf install ./hermes-kms-seatd-0.4.1-1.fc44.noarch.rpm
```

Install the **kernel headers/devel matching your target kernel**, then confirm
`dkms status -m hermes-kms` reports 0.4.1 installed for that kernel.
Secure Boot may require module signing and key enrollment. Reboot to activate
the updated module; do not force-unload it from a running compositor.
For optional private sessions, configure the user with
`sudo /usr/lib/hermes-kms/hermes-kms-setup configure --user auto`.

**Bazzite / bootc / immutable systems:** Do **not** install the regular Fedora
DKMS RPM into an immutable image. Use the
[image-based instructions](https://github.com/MrOz59/Hermes-KMS/blob/v0.4.1/README.md#image-based-systems-bazzite-and-compatible-bootcostree-images)
instead. The Fedora 44 RPMs are not claimed to be runtime-validated on
other Fedora versions.

## Hermes ecosystem installer

The planned all-in-one installer for Hermes and its components belongs in the
**[Hermes repository](https://github.com/MrOz59/Hermes)**, not Hermes-KMS.
It is **not included in this driver release**. The packages above can be
installed independently; they do not install Hermes, Hestia or libvirtualhid.

## Validation and remaining limits

All **seven release CI jobs passed**, covering userspace/UAPI/EDID checks,
kernel builds against Arch, Ubuntu and Fedora headers, and the packaged
DKMS/DEB/RPM payloads. Bazzite VM image deployment was tested in #20.
These checks do **not** replace an end-to-end real-GPU test: SDR/HDR hardware
streaming, upgrade/reboot and simultaneous isolated Gamescope sessions still
need broader validation. Please report regressions with your kernel version,
GPU, package format and logs.
